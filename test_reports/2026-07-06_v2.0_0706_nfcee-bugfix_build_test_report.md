## 2. 測試範圍與方法

測試目標：確認修復的 8 個 bug（7 處 NFCEE ID 範圍收斂 + 1 處 `val_payload`）在打包後的行為正確，且沒有破壞範圍收斂本身原本就正常的部分。

**方法與環境限制**（與前次打包報告相同的既有限制，詳見專案記憶 `project_console_app_cp950_encoding_issue`）：對打包後的 `.exe` 嘗試用管道輸入驅動互動選單，仍受限於既有、與本次修改無關的 `cp950` 選單編碼問題，`PYTHONIOENCODING` 對凍結後的 exe 無效。因此本次驗證改採：(a) 確認 PyInstaller 打包記錄顯示異動模組都正確分析、無 import 錯誤；(b) 對封裝進 exe 的**相同原始碼**（本次打包前才剛清除快取重新分析，可確保是最新版本）直接用函式呼叫方式驗證全部 8 個修復點，含使用者回報的 2 筆原始測資、`FF` 邊界值、以及正常動態範圍值（`50`）三種情境。

## 4. 既有問題（非本次修改造成，沿用先前報告記錄）

- 主控台選單在 stdout 非真正互動式主控台時的 `cp950` 編碼問題仍然存在，本次打包測試同樣受此限制，僅能透過原始碼函式層級驗證，無法自動化跑完整互動選單。詳見 `test_reports/2026-07-06_v2.0_0706_build_test_report.md` 與專案記憶。

## 5. 結論

打包成功，本次修復的 8 個 bug（NFCEE ID 範圍收斂造成的 1 個 crash + 6 個重複輸出，以及 `RF_SET_FORCED_NFCEE_ROUTING_CMD` 獨立的 `val_payload` crash）全數驗證通過，涵蓋使用者回報的原始測資、邊界值（`FF`）與正常動態值（`50`）三種情境，vendor=None 與 vendor=Nxp 兩條路徑皆確認無誤。建議使用者在真正的終端機視窗手動執行一次 exe，用原始回報的兩筆測資做最終視覺確認。
