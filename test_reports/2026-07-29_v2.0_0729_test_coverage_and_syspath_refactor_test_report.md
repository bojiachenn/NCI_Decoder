## 2. 測試範圍與方法

這次是本專案第一次有自動化測試(先前是 0 個)。新增 pytest 基礎建設(`conftest.py` → 後續驗證後移除，見下)、`pytest.ini`、`requirements-dev.txt`、`tests/` 骨架,並補齊三層測試:

- **Tier 1**(`tests/test_log_profiles.py`,31 個):`log_profiles.py` 純函式,含 ST/NXP 兩種 log profile 的判斷與擷取邏輯。
- **Tier 2**(`tests/test_decoder_main.py`,8 個):`Decoder_Main.NFC_NCI_DECODER` 派工邏輯,含 GID/OID 命中派工(`vendor=None`/`vendor=Nxp` 兩條路徑)、`KeyError`/`ERROR_NOT_FOUND` 例外路徑、payload 長度不符錯誤、DATA 封包分支、HDLL(2-byte header+CRC16)分支、PBF flag 分支、"Unknown raw data!" fallback 分支。
- **Tier 3**(`tests/nfc_forum_2_0_pkg/test_nfcee_range_regressions.py`,54 個):commit `5f5cb72` 修復的 8 個 bug(7 處 NFCEE ID 範圍收斂 crash/重複輸出 + 1 處 `val_payload` crash)的邊界值回歸測試,針對 `00`/`01`/`FF`(超出三個宣告 range 的邊界值)與 `50`(正常動態值,對照組)四種輸入,每個 handler 都跑 `vendor="None"` 與 `vendor="Nxp"` 兩條路徑。

**唯一真正改變執行路徑的變更**是 `nci_decoder/__init__.py` 的 sys.path 重構,額外驗證方法(既有 `cp950` 環境限制詳見專案記憶 `project_console_app_cp950_encoding_issue`):

- (a) 全部 93 個 pytest 案例分別在專案根目錄 (`E:\Project\NCI_Decoder\NCI_Decoder`) 與非根目錄 (`E:\Project\NCI_Decoder`,以 `pytest NCI_Decoder` 呼叫) 各跑一次,確認 `__file__`-relative 修法真的讓執行結果不再依賴 CWD。
- (b) 承 (a) 的結果,把 `conftest.py` 原本用來繞過 CWD-relative sys.path 問題的 `os.chdir` workaround **完全移除**並重新驗證全部測試仍通過(兩種 CWD 皆通過)——這證實重構後這個 workaround 確實已無必要,不是用猜的。
- (c) 對封裝進 exe 的**相同原始碼**,用 `PYTHONIOENCODING=utf-8` 執行 `python Decoder.py`,以管道輸入驅動互動選單跑 mode 2(單筆 raw hex `20000101`,對應 `CORE_RESET_CMD`),確認完整 CLI 流程(非僅測試裡直接呼叫函式)在重構後仍正確解碼。
- (d) 直接啟動打包後的 `dist/NCI_Decoder_v2.0_0729.exe`,以管道輸入驅動,確認 `import nci_decoder`(觸發重構後的 sys.path 設定邏輯)到 `main()` 開始執行全程無 `ImportError`/`ModuleNotFoundError`,程序一路執行到選單橫幅列印才撞上**既有、與本次變更無關**的 `cp950` 編碼 crash(嘗試過 `chcp 65001` 切換主控台編碼頁與 `winpty` 附加真正的虛擬終端機,結果相同,確認非本次改動引入)。

- 主控台選單在 stdout 非真正互動式主控台時的 `cp950` 編碼問題仍然存在;本次額外嘗試 `chcp 65001` 與 `winpty` 附加虛擬終端機兩種方式,結果相同,確認與本次的 `__init__.py` 重構無關,純粹是既有限制。詳見專案記憶 `project_console_app_cp950_encoding_issue`。

## 5. 已知的測試設計取捨

- Tier 3 對 `RF_SET_FORCED_NFCEE_ROUTING_CMD` 也做了 `vendor="Nxp"` 參數化,但 `Nxp_pkg/RF_Management.py` 裡這個函式是 no-op stub(從不轉呼叫 forum 版本),所以這個組合是真實 dispatcher 底下不會發生的假覆蓋——為了 7 個 handler 規則一致而保留,測試檔案裡已用註解說明。

## 6. 結論

本次新增了 93 個自動化測試(Section A 測試基礎建設 + 三層測試),並完成 `nci_decoder/__init__.py` 唯一的行為變更(sys.path 由 CWD-relative 改為 `__file__`-relative,移除殘留 debug print,`conftest.py` 的 CWD workaround 經驗證後移除)。封裝後的 `NCI_Decoder_v2.0_0729.exe` 確認 import 鏈在重構後無異常,唯選單互動驗證仍受既有 `cp950` 限制無法全自動跑完,建議使用者在真正的終端機視窗手動執行一次 exe 做最終視覺確認。
